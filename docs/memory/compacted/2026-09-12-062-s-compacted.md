## What shipped

A standalone, disposable Python CLI preprocessor
(`scripts/hashicorp_mdx_normalize.py` + `scripts/_hashicorp_mdx/{selection,
normalize}.py`) that selectively copies the latest-version directory of each
versioned HashiCorp product (plus all unversioned products) from an
external, read-only corpus, normalizing `.mdx -> .md` in-flight during copy.
Produces coverage + unhandled-construct-inventory JSON as requirements
evidence for a future first-class `docline` MDX ingestion feature.
Explicitly, permanently out of scope: production `docline` MDX
integration — no `src/docline/` runtime surface is touched.

## Key decisions and rationale

* **Standalone `scripts/` placement, no `src/docline/` dependency**: keeps
  the disposable tool fully decoupled from the product's ingestion
  pipeline; `.mdx` was never added to `_SUPPORTED_EXTENSIONS`.
* **Python semver port of the source repo's `gather-version-metadata.mjs`**,
  validated against a checked-in expected-latest table plus a full-corpus
  live cross-check — chosen over a naive sort because latest-version
  selection has real, non-obvious edge cases (`vault -> v2.x` not
  `v1.21.x`; `terraform-enterprise` date-string fallback; beta-stage
  exclusion). The compound learning "third-party API shape requires live
  verification" (`docs/compound/2026-09-09-third-party-api-shape-requires-
  live-verification.md`) was applied proactively at Stage triage and paid
  off: live corpus verification found real corrections vs. the plan's
  assumed values (`terraform-enterprise` had newer semver-style dirs the
  original investigation missed).
* **Streaming normalize-on-copy, never materialize-then-normalize**:
  `.mdx -> .md` transforms happen in-flight per file so no intermediate
  `.mdx` is ever written at `--dest`.
* **Dry-run-by-default, `--execute` never run by an agent**: the only
  human-in-the-loop gate this tool needs. The exact operator command is
  documented in the script's own `--help` epilog and in the
  requirements-evidence doc; no session agent ever ran it against the real
  external destination (confirmed 0 entries before/after, every session).
* **Exclusive sentinel-file destination claim** (review-fix cycle 3,
  superseding an earlier `mkdir(exist_ok=False)` design): an operator's
  real `--dest` can legitimately pre-exist (empty) from a prior read-only
  inspection, which `mkdir(exist_ok=False)` cannot distinguish from an
  actively-claimed concurrent invocation. Redesigned around an
  `os.O_CREAT | os.O_EXCL` sentinel file as the sole claim signal,
  decoupling "does `--dest` exist" from "is `--dest` claimed". Captured as
  a durable compound learning:
  `docs/compound/2026-09-12-exclusive-destination-claim-needs-sentinel-not-mkdir.md`.
