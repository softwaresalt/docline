## What shipped

Browserless discovery-source seam (`link_sources.py`) + Terraform Registry v2 JSON:API adapter
(`tf_registry_source.py`), composed additively into `crawl()`. `CrawlConfig.enable_api_discovery`
threaded end-to-end through `FetchRequest`/`WebCrawlSource`/`ManifestUrlSource` as an operator
kill switch. Fixes the operator's reported one-page-only SPA-shell defect for
`web_crawl` of Terraform Registry provider-docs URLs.

## Key decisions and rationale

* **Browserless by design**: headless-browser investigation found the registry's sidebar is
  virtualized/API-driven, exposing only ~39/1,620 docs even fully expanded — a browser
  dependency would still be structurally incomplete. API-backed discovery instead.
* **Composition point in `crawl.py`**: registers the concrete adapter at import time so the
  generic seam (`link_sources.py`) never imports a concrete provider — a future second adapter
  only needs a new registration line.
* **Check-before-pull frontier admission**: the discovery seed checks `max_frontier`/`max_pages`
  budgets *before* pulling each item from the adapter's async generator (not after, unlike the
  existing static-anchor admit-then-check pattern), so a paginated API source is never driven to
  fetch a page that can never be admitted or processed.
* **Fail-open degradation**: any adapter failure (narrow `DoclineError`) degrades to static-only
  extraction with one WARNING log; budget/SSRF errors propagate unwrapped (I4 carve-out) at both
  the adapter and composition layers.
* **Real API shape correction (critical, live-verification-only finding)**: the plan's assumed
  `relationships["latest-version"]` singular relationship does **not exist** in the real
  Terraform Registry v2 API — confirmed only by live querying, undetectable by any fixture-based
  test. Fixed by selecting the maximum `published-at` timestamp across the real `included`
  provider-versions set.
