For ManifestUrlSource, ALSO credential-redact config.id via a new sanitize_source_id(raw_id: str) -> str helper that is TOTAL, non-throwing, and MARKER-GATED: it does NOT delegate to sanitize_source() (whose path/file:// redaction and fragment drop would mangle a credential-free id and whose _sanitize_url() can raise); it (a) detects credential markers with a non-throwing scan over a DECODED VIEW (user:pass@ userinfo, and key=value fragments whose key matches the EXISTING _CREDENTIAL_PARAM_PREFIXES vocabulary, reuse do NOT expand; never calls urllib .port); [R8] classify parameter names over a BOUNDED MULTI-LAYER decode of each name token: layer0=raw, layer_{i+1}=urllib.parse.unquote(layer_i, encoding=utf-8, errors=replace), stop at a fixed point OR after _MAX_CREDENTIAL_DECODE_LAYERS=5 passes; a name is a MARKER if _is_credential_param matches at ANY layer, so single- AND multi-layer encodings (%74oken, %2574oken, ...) of a credential key are recognized (supersedes the R7 single pass, which left double-encoded keys un-redacted and leaking). Termination is guaranteed (each non-fixed-point pass removes >=1 decodable %HH escape; hard-bounded by the cap); errors=replace makes malformed/non-UTF8 sequences (%zz, truncated %e0) total and non-throwing. FAIL CLOSED: if the loop hits the cap WITHOUT a fixed point (still decoding), treat as a marker and redact the value; a fixed-point name still carrying invalid %zz is NOT ambiguous and, absent a marker, is preserved verbatim. The decoded view is DETECTION-ONLY, (b) returns a credential-free id byte-for-byte VERBATIM regardless of shape (absolute path /source-a, file://, fragment-bearing URL https://host/x#frag), (c) surgically redacts recognized credential fragments/userinfo when a marker is present, over the RAW bytes so an encoded key is preserved and only the value redacted (srcA?token=SECRET -> srcA?token=<redacted>; srcA?%74oken=IDSECRET -> srcA?%74oken=<redacted>), and (d) FAILS CLOSED to <source-id-redacted> for a marker-bearing input it cannot surgically redact -- never raw, never raising. Build the manifest prefix from f"manifest_url:{sanitize_source_id(config.id)}" before recompose. Because both steps are fail-closed, sanitize_source_key(config) is TOTAL and safe to call before the fetch try (metadata build) and inside the exception logger without crashing _execute_single_source or masking a fetch failure. make_job_id still hashes the RAW build_source_key(config) so job_id determinism is unchanged.
