Author the failing shared-fetch resource-exhaustion harness in the fetch test suite (tests/fetch/) (test-first / red). Tests domain only. Cycle-2 review found FetchRequest.max_pages has no upper bound (src/docline/app_models.py:25) and each response is buffered with an unbounded response.read() (src/docline/fetch/http.py:123), so a small valid request can exhaust memory/network on the untrusted MCP surface. This harness pins the required page/work cap and streamed response-byte cap on the SHARED fetch code (affects CLI and MCP). See docs/plans/2026-08-27-mcp-stdio-server-plan.md (Plan Hardening H7).

<!-- BEGIN:acceptance-criteria -->
- FetchRequest.max_pages above the hard upper bound MAX_PAGES_LIMIT = 1000 (i.e. >=1001) is rejected at model validation (ValidationError / -32602 on the MCP boundary); max_pages 1..1000 inclusive is accepted (plan §H7 Selected numeric limits).
- Per-response byte cap (parametrized: initial response AND the terminal response returned after a redirect): a body exceeding MAX_RESPONSE_BYTES = 10 MiB (10485760 bytes) is aborted without fully buffering it (streamed read; assert the read is chunked/bounded, not a single response.read()); a body of exactly 10485760 bytes is allowed. Exact-boundary over-read guard: the harness drives an over-cap body through a fake/instrumented transport that records every read size, and asserts the reader consumes AT MOST MAX_RESPONSE_BYTES + 1 total bytes (only the single crossing byte) before aborting - NOT MAX_RESPONSE_BYTES + CHUNK_SIZE (a whole extra chunk) - and that each individual read request is bounded by min(CHUNK_SIZE, remaining_response_bytes + 1). NOTE (cycle-10): the "redirect" case here is the FINAL response opener.open() returns after following redirects; the INTERMEDIATE 3xx redirect-body cap (urllib's in-handler unbounded fp.read()) is a separate width-isolated vector proven by 064.027-T and greened by 064.028-T.
- All new tests observed FAILING before implementation (red) - no upper bound / no byte cap exists yet.
- Scenario budget: 2 (max_pages cap, per-response streamed cap [init+redirect parametrized]) - within the <4 heuristic. NOTE (cycle-3): the aggregate MAX_TOTAL_FETCH_BYTES budget moved to its own byte-accurate pair (064.016-T harness / 064.017-T impl) so this harness stays width-isolated to the per-dimension caps.
