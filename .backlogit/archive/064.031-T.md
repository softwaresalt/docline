Author the RED §H8 adapter-policy harness (tests/parity/test_mcp_stdio.py). Tests domain only. Proves the DoclineMcpServer adapter enforces the external-PDF-engine gate on the untrusted MCP surface at the INSTANCE level - both the advertise surface (list_callable_tools) and the dispatch surface (call_tool / process) - default-DENY via a local-engine ALLOW-LIST, with external engines available only when the server carries the explicit server-side opt-in. Mirrors §H1 (workspace_root omitted from schema AND rejected at dispatch) as the THIRD sanctioned MCP-only parity divergence. PR #166 post-decomposition cycle-3 finding (Copilot thread PRRT_kwDOSsAX4c6dWm-8): the MCP-specific process schema inherits pdf_engine="mistral_ocr", letting an untrusted local MCP caller consume ambient Foundry/Mistral credentials and base64-upload workspace PDFs to an external paid OCR endpoint. Ground truth: request.pdf_engine is the SOLE client-controllable selector of the external reader (readers/pdf.py auto-policy never resolves to mistral_ocr; docling is local; pdf_mode=triage ignores layout_engine; MISTRAL_OCR_MODEL only renames an already-selected engine). An ALLOW-LIST (not a mistral_ocr deny-list) is used so any FUTURE external engine is denied by default. Verifies red until 064.032-T. See docs/plans/2026-08-27-mcp-stdio-server-plan.md (Plan Hardening §H8).
