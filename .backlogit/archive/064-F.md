Make docline usable over a local stdio MCP connection by adding a runnable JSON-RPC 2.0 stdio server that wraps the existing DoclineMcpServer adapter, and ship a docline-mcp console executable (docline-mcp.exe on Windows). Source stash: 14E46B47. The adapter, shared manifest, and transport guard already exist; this feature adds the missing runnable protocol surface + entry point, hardened for the untrusted stdio boundary. Executable — no external credentials, paid calls, or corpora required. Ranked high product-outcome (interoperability/composability outranks feature novelty).

The stdio loop reads frames NON-GREEDILY (read1/os.read, never blocking to fill a whole CHUNK_SIZE) and FLUSHES stdout after every response, and an INTERACTIVE automated subprocess smoke test (subprocess.Popen: send+flush one frame, require its response BEFORE sending the next with stdin still open, then EOF; timeout-bounded reads) proves no live stdio deadlock and asserts advertised-tool-name parity (064.008-T green@064.003-T). The non-greedy-read + per-frame-flush liveness properties are FIRST observed RED in-process by 064.001-T's instrumented serve() liveness assertion (injected non-greedy stdin + flush-recording stdout; green@064.002-T), so the transport behaviors are observed red before implementation (strict test-first); 064.008-T is retained as the live subprocess / packaging smoke.

- JSON-RPC conformance: -32600 Invalid Request for non-object root / bad-or-missing jsonrpc / a method that is not a present non-empty string (absent/non-string/empty) / present non-string-non-number id (object/array/bool/null - MCP 2026-07-28 RequestId permits only string|number; a malformed or absent id is never echoed, the -32600 frame carries id:null, but a VALID present id accompanying a non-id defect IS echoed for response correlation; id-absence is decided by key membership not truthiness, so a present id:0 or id:"" receives a normal echoed response, never suppression; an absent id on an OTHERWISE-VALID request stays an id-less notification (silent, even for an unknown method or malformed params), but an absent id on a MALFORMED payload (non-object root / bad-or-missing jsonrpc / missing-or-non-string/empty method, canonically {"jsonrpc":"2.0"} with no method and no id) is NOT suppressed and returns -32600 with id:null - request-shape validation over {root,jsonrpc,method,id-type} precedes the id-absent notification-suppression branch (params validation is post-suppression, id-bearing only); a present null id is -32600). Because request-shape validation runs before era routing in the single hardened dispatch, both eras reject a malformed id identically. -32700 parse error for invalid JSON, INCLUDING Python's permissive non-finite JSON constant TOKENS NaN / Infinity / -Infinity, which the frame parse rejects via a strict parse_constant callback (before the id-type guard and era routing); AND, because numeric OVERFLOW literals (e.g. 1e400 -> float inf) bypass parse_constant, the id-type guard additionally rejects a non-finite numeric id via math.isfinite() as -32600 (id:null) - so no non-finite number (token or overflow form) can pass the string-or-number id guard or be re-emitted by json.dumps as a bare non-JSON token, guaranteeing no non-finite number enters RequestId or any response serialization (both eras inherit both guards; serialization uses allow_nan=False and degrades a stray ValueError to -32603 rather than crashing the loop).
