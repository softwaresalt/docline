Implement the guarded IPv4-mapped normalization and the explicit CGNAT `100.64.0.0/10` membership
check in `_is_unsafe_address` (`src/docline/fetch/sitemap.py`) to green the 065.001-T harness. Code
domain only (single module, <=1 function touched + one module-level constant). Depends on 065.001-T.
See `docs/plans/2026-08-28-sitemap-cgnat-ssrf-gap-plan.md`.

<!-- BEGIN:acceptance-criteria -->
- Add a module-level constant `_CGNAT_NETWORK = ipaddress.ip_network("100.64.0.0/10")` (stdlib `ipaddress` already imported; no new dependency).
- In `_is_unsafe_address`, BEFORE the existing six-flag classification and the CGNAT check, normalize an IPv4-mapped IPv6 literal to its embedded IPv4 address, **guarded for `IPv6Address` only**: `if isinstance(ip, ipaddress.IPv6Address) and ip.ipv4_mapped is not None: ip = ip.ipv4_mapped`. Do NOT write an unguarded `ip = ip.ipv4_mapped or ip` — `IPv4Address` has no `.ipv4_mapped` attribute, so that would raise `AttributeError` on ordinary IPv4 input (e.g. `100.64.0.1`, `93.184.216.34`) and break the classifier. Only `::ffff:0:0/96` maps; the deprecated IPv4-compatible `::/96` form is not reinterpreted (its `.ipv4_mapped` is `None`, already rejected as IPv6 `is_reserved`).
- Apply the six-flag classification AND the CGNAT membership check to the NORMALIZED `ip`. Reject (return `True`) when `ip.version == 4 and ip in _CGNAT_NETWORK` (version-guarded so a still-IPv6 address never mis-tests against the IPv4 network). Preserve the existing fail-closed `ValueError` handling and `_METADATA_IPS` check; the normalization + CGNAT clause is additive.
- All 065.001-T CGNAT rows pass — including the IPv4-mapped literal rows (`::ffff:100.64.0.1` rejected via `_is_unsafe_address`; `http://[::ffff:100.64.0.1]/sitemap.xml` rejected via `validate_sitemap_url`) — plus class-pin, IP-literal, resolved-host/rebinding, and boundaries `100.64.0.0`/`100.127.255.255` rejected; and the boundary-accept rows (`100.63.255.255`, `100.128.0.0`, IPv4-mapped `::ffff:100.63.255.255`, public-unicast) stay accepted — no over-rejection.
- All pre-existing `tests/fetch/test_sitemap.py` rows remain green (no behavior change for loopback/private/link-local/multicast/reserved/unspecified/metadata classes; non-mapped IPv4/IPv6 inputs are unchanged by the normalization).
- Update the module docstring's SSRF-classification note (step 5) to record the IPv4-mapped normalization step and to include CGNAT `100.64.0.0/10` among the rejected classes, keeping the documented contract accurate.
- Quality gates green: `ruff check .`, `ruff format --check .`, `pyright src/`, `pytest tests/fetch/test_sitemap.py`.
