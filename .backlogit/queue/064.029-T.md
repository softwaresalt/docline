Author the failing redirect-hop fetch-attempt-debit PLACEMENT harness in the fetch test suite (tests/fetch/) (test-first / red). Tests domain only. Cycle-12 (PR #166 Copilot cycle-3 Finding B) found the cycle-11 mechanism debited ONE MAX_FETCH_ATTEMPTS fetch-attempt inside the http_error_302 override BEFORE delegating to super() - too EARLY. stdlib HTTPRedirectHandler.http_error_302 performs Location resolution, scheme check, loop detection, and calls redirect_request (which also runs the §H6 address-pinned revalidation) - ANY of which can REJECT the redirect before parent.open() (the outbound I/O) is ever reached. Debiting before super() therefore charges a fetch-attempt even for redirects that policy/scheme/loop validation REJECTS (no outbound request happens), corrupting the request-COUNT accounting. This harness pins that the redirect-hop attempt debit is placed on the SUCCESSFUL next-request path ONLY: exactly one MAX_FETCH_ATTEMPTS debit per FOLLOWED hop, occurring inside _ValidatingRedirectHandler.redirect_request AFTER the stdlib scheme check (raised in http_error_302 BEFORE redirect_request) and the §H6 address-pinned revalidation, immediately BEFORE it returns a non-None Request (i.e. before the parent.open() outbound I/O) - and NO debit when a redirect is rejected by the scheme check or by §H6/stdlib redirect_request. The redirect_request placement NEVER UNDER-counts (every followed hop is debited before its parent.open) - a bounded, CONSERVATIVE over-count residual on the stdlib loop-detection and body-drain-breach paths is documented below and is safe for a DoS upper bound (it can only make the budget trip earlier, never allow more outbound work than MAX_FETCH_ATTEMPTS). The redirect_request placement (over a body-proxy-close placement, which would be exact but re-entangle attempt accounting into 064.028's body-drain proxy) is chosen to keep the attempt concern WIDTH-ISOLATED from the body drain per the cycle-12 decomposition. This is the redirect-hop half of the §H7 item-4a request-amplification bound, DECOMPOSED out of the redirect-body drain pair (064.027-T/064.028-T) into its own width-isolated concern. Redirect hops are debited from the SAME request-scoped RemainingByteBudget threaded into the handler by 064.028-T (attempt allowance seeded by 064.026-T); 064.025-T covers the direct-outbound-call boundary debits (robots/TOC/retries). This harness affects the SHARED fetch code (CLI docline fetch and the MCP fetch tool). See docs/plans/2026-08-27-mcp-stdio-server-plan.md (Plan Hardening H7 item 4a, redirect-hop attempt debit; cycle-12 placement remediation).
