PLAN Unit 1 (code; test-first). CONTRACT R5 (typed-config; url sanitized + id credential-redacted INDEPENDENT of URL detection; supersedes the R2 scheme-anchor string parse (PR #194 thread PRRT_kwDOSsAX4c6hzYmm) and the R3/R4 sanitize_source()-only id handling (PR #195 threads PRRT_kwDOSsAX4c6h0OMq/PRRT_kwDOSsAX4c6h0OM1)). Keep _build_crawl_source_key and its existing _crawl_option_parts option construction AS-IS as the single builder grammar in src/docline/elt/source_keys.py, reused by both build_source_key and the new sanitizer (no new _CRAWL_OPTION_KEYS constant: the typed-config recompose removes the separate parse path a shared option-key constant would guard). Add sanitize_source_key(config: SourceConfig) -> str that consumes the TYPED config (NOT the composed key string): for the two leak-scoped crawl configs (WebCrawlSource, ManifestUrlSource) sanitize the typed config.url via the existing public sanitize_source() (reuse, do not duplicate _CREDENTIAL_PARAM_PREFIXES) and RECOMPOSE the key through _build_crawl_source_key with the sanitized url, so the sanitized key is grammar-identical to the raw key except for the URL segment (immune to the manifest_url:<id>:<url> scheme-in-id ambiguity because no composed string is parsed; ManifestUrlSource.id is an unrestricted str per manifest_models.py:65). For ManifestUrlSource, ALSO credential-redact config.id via a new sanitize_source_id() helper that redacts INDEPENDENT of URL detection -- apply sanitize_source() for URL/path-shaped ids AND, regardless of scheme, strip user:pass@ userinfo and redact credential-named key=value fragments using the EXISTING _CREDENTIAL_PARAM_PREFIXES vocabulary (reuse, do NOT expand) -- and build the prefix from the redacted id (f"manifest_url:{sanitize_source_id(config.id)}") before recompose, because id is unrestricted: a scheme-bearing OR a non-URL-form credential-bearing id (e.g. srcA?token=SECRET) would otherwise leak into metadata.source and the ERROR log, and routing id through sanitize_source() alone is a no-op on non-URL-form ids (PR #195 Copilot findings PRRT_kwDOSsAX4c6h0OMq/PRRT_kwDOSsAX4c6h0OM1); make_job_id still hashes the RAW build_source_key(config) so job_id determinism is unchanged. All other config types (LocalFileSource, GitHubRepoSource, ManifestLocalSource, ManifestGitSource) return build_source_key(config) BYTE-IDENTICAL (github_repo token handling DEFERRED). Add sanitize_source_key and sanitize_source_id to __all__; update module docstring. make_job_id keeps hashing the raw build_source_key(config). Files: src/docline/elt/source_keys.py, tests/elt/test_source_keys.py (new). Size: S | Complexity: medium. ACCEPTANCE CRITERIA: (1) web_crawl config with userinfo + ?token=SECRET + options -> token+userinfo absent, prefix+option suffixes preserved; (2) a ManifestUrlSource whose id is itself a credential-bearing scheme-bearing string (userinfo + ?token=IDSECRET) and whose url carries ?token=SECRET -> BOTH SECRET and IDSECRET (and any userinfo) ABSENT from the recomposed key while the non-credential prefix/id-host/options are preserved; AND a NON-URL-form credential-bearing id (srcA?token=IDSECRET, no scheme) with IDSECRET ABSENT from the recomposed key (proves ID-specific redaction is INDEPENDENT of URL detection -- the R5 case where routing id through sanitize_source() alone was a no-op -- and that the typed-config recompose is immune to scheme-in-id, the case the R2 string parse could not handle); (3) github_repo/local_file configs returned byte-identical AND an empty-option credentialed web_crawl config sanitized; (4) new unit tests pass; make_job_id input (raw build_source_key(config)) is not touched by the helper.
