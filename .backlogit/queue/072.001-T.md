PLAN Unit 1 (code; test-first). CONTRACT R6 (typed-config; url sanitized fail-closed + id credential-redacted INDEPENDENT of URL detection; helper TOTAL/non-throwing; supersedes the R2 scheme-anchor string parse (PR #194 thread PRRT_kwDOSsAX4c6hzYmm), the R3/R4 sanitize_source()-only id handling, and the R5 sanitize_source()-delegating id path (PR #195 threads PRRT_kwDOSsAX4c6h0dUG/PRRT_kwDOSsAX4c6h0dUO)). Keep _build_crawl_source_key and its existing _crawl_option_parts option construction AS-IS as the single builder grammar in src/docline/elt/source_keys.py, reused by both build_source_key and the new sanitizer (no new _CRAWL_OPTION_KEYS constant). Add sanitize_source_key(config: SourceConfig) -> str that consumes the TYPED config (NOT the composed key string): for the two leak-scoped crawl configs (WebCrawlSource, ManifestUrlSource) sanitize the typed config.url via the existing public sanitize_source() (reuse, do not duplicate _CREDENTIAL_PARAM_PREFIXES) INSIDE A FAIL-CLOSED WRAPPER -- sanitize_source()/_sanitize_url() reads parsed.port which raises ValueError on a malformed URL such as https://host:notaport, so on any ValueError the url yields the sentinel <source-url-redacted> instead of propagating -- and RECOMPOSE the key through _build_crawl_source_key with the sanitized url. For ManifestUrlSource, ALSO credential-redact config.id via a new sanitize_source_id(raw_id: str) -> str helper that is TOTAL, non-throwing, and MARKER-GATED: it does NOT delegate to sanitize_source() (whose path/file:// redaction and fragment drop would mangle a credential-free id and whose _sanitize_url() can raise); it (a) detects credential markers with a non-throwing string/regex scan only (user:pass@ userinfo, and key=value fragments whose key matches the EXISTING _CREDENTIAL_PARAM_PREFIXES vocabulary, reuse do NOT expand; never calls urllib .port), (b) returns a credential-free id byte-for-byte VERBATIM regardless of shape (absolute path /source-a, file://, fragment-bearing URL https://host/x#frag), (c) surgically redacts recognized credential fragments/userinfo when a marker is present (srcA?token=SECRET -> srcA?token=<redacted>), and (d) FAILS CLOSED to <source-id-redacted> for a marker-bearing input it cannot surgically redact -- never raw, never raising. Build the manifest prefix from f"manifest_url:{sanitize_source_id(config.id)}" before recompose. Because both steps are fail-closed, sanitize_source_key(config) is TOTAL and safe to call before the fetch try (metadata build) and inside the exception logger without crashing _execute_single_source or masking a fetch failure. make_job_id still hashes the RAW build_source_key(config) so job_id determinism is unchanged. All other config types (LocalFileSource, GitHubRepoSource, ManifestLocalSource, ManifestGitSource) return build_source_key(config) BYTE-IDENTICAL (github_repo token handling DEFERRED). Add sanitize_source_key and sanitize_source_id to __all__; update module docstring. Files: src/docline/elt/source_keys.py, tests/elt/test_source_keys.py (new). Size: S | Complexity: medium. ACCEPTANCE CRITERIA: (1) crawl URL redaction + fail-closed: web_crawl config with userinfo + ?token=SECRET + options -> token+userinfo absent, prefix+option suffixes preserved; AND a MALFORMED url (https://host:notaport?token=SECRET, where _sanitize_url's parsed.port would raise) -> sanitize_source_key() returns WITHOUT raising, SECRET absent, url segment is the <source-url-redacted> sentinel; (2) ManifestUrlSource.id handling parametrized: (a) scheme-bearing credential id (userinfo + ?token=IDSECRET), (b) non-URL-form credential id (srcA?token=IDSECRET, no scheme) -> in both IDSECRET+userinfo ABSENT while non-credential id/prefix/options preserved (redaction independent of URL detection), (c) MALFORMED credential-bearing id (https://u:p@host:notaport?token=IDSECRET) -> sanitize_source_id() FAILS CLOSED to <source-id-redacted> without raising, IDSECRET absent, (d) credential-free absolute-path id /source-a and (e) credential-free fragment-bearing URL id https://host/x#frag each returned VERBATIM byte-for-byte (no path-redaction, fragment retained); (3) github_repo/local_file configs returned byte-identical AND an empty-option credentialed web_crawl config sanitized; (4) new unit tests pass and make_job_id input (raw build_source_key(config)) is not touched by the helper (determinism).
