Covering release unit (security remediation) for stash D6E758F5, a P2 credential leak surfaced by 059-S. _execute_single_source persists and ERROR-logs a raw web_crawl/manifest_url source_key whose embedded URL carries userinfo + credential query params, because sanitize_source() is a no-op on the crawl-prefixed key. Fix adds a typed-config sanitize_source_key(config) helper (R7 contract; supersedes the R2 scheme-anchored string parse per Copilot review on PR #194 and the R3/R4/R5 id handling per Copilot review on PR #195) that sanitizes BOTH the manifest id and the crawl url and recomposes the key via the existing _build_crawl_source_key builder grammar. sanitize_source_key() and sanitize_source_id() are TOTAL and non-throwing: sanitize_source()/_sanitize_url() reads parsed.port which raises ValueError on a malformed URL (e.g. https://host:notaport), so the url sanitize is wrapped fail-closed (yields <source-url-redacted>) and sanitize_source_id() never delegates to that throwing path -- it is marker-gated, returns a credential-free id VERBATIM (byte-for-byte, no path/fragment mangling) regardless of shape (absolute path, file://, fragment-bearing URL), redacts only recognized credential fragments/userinfo (existing _CREDENTIAL_PARAM_PREFIXES vocabulary, not expanded) when a marker is present, and FAILS CLOSED to <source-id-redacted> for a marker-bearing input it cannot surgically redact (so a non-URL-form id like srcA?token=SECRET -> srcA?token=<redacted> rather than a no-op, and a malformed credentialed id never leaks or raises). The R7 refinement makes sanitize_source_id() marker detection classify credential parameter names on a single-unquote decoded view mirroring parse_qsl (utf-8, errors=replace, no .port), so a percent-encoded credential key such as %74oken=IDSECRET (decoding to token) is recognized and surgically redacted (encoded key preserved, only the value redacted) instead of bypassing the gate; the decode is detection-only and the bounded single pass keeps id/url handling consistent for double-encoded and malformed/non-UTF8 percent sequences (closes PR #195 threads PRRT_kwDOSsAX4c6h05Dd/PRRT_kwDOSsAX4c6h05Ds). Both sinks (metadata.source persistence + ERROR log incl. traceback) route through sanitize_source_key(config), while make_job_id keeps hashing the raw build_source_key(config) so job_id determinism is preserved and the helper is safe to call before the fetch try and inside the exception logger. Supersedes R3/R4/R5 per PR #195 Copilot threads PRRT_kwDOSsAX4c6h0dUG/PRRT_kwDOSsAX4c6h0dUO. Source plan: docs/plans/2026-09-12-source-key-credential-sanitization-plan.md.
