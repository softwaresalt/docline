Covering release unit (security remediation) for stash D6E758F5, a P2 credential leak surfaced by 059-S. _execute_single_source persists and ERROR-logs a raw web_crawl/manifest_url source_key whose embedded URL carries userinfo + credential query params, because sanitize_source() is a no-op on the crawl-prefixed key. Fix adds a typed-config sanitize_source_key(config) helper (R5 contract; supersedes the R2 scheme-anchored string parse per Copilot review on PR #194 and the R3/R4 sanitize_source()-only id handling per Copilot review on PR #195) that sanitizes BOTH the manifest id and the crawl url and recomposes the key via the existing _build_crawl_source_key builder grammar. For ManifestUrlSource the unrestricted id is credential-redacted INDEPENDENT of URL detection (sanitize_source_id: strips userinfo + redacts credential-named key=value fragments using the existing _CREDENTIAL_PARAM_PREFIXES vocabulary, so a non-URL-form id like srcA?token=SECRET is redacted to srcA?token=<redacted> rather than left as a no-op), and config.url is sanitized via the existing sanitize_source() URL logic; both are routed through the metadata.source persistence sink and the ERROR log (incl. traceback), while keeping make_job_id on the raw build_source_key(config) so job_id determinism is preserved. Source plan: docs/plans/2026-09-12-source-key-credential-sanitization-plan.md. NOT bundled with 059-S/060-S. github_repo token leak and credential-list expansion are deferred (P-021 watch).
