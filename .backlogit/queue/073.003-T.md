Stream B / Unit B1 (test domain, test-first). Add parametrized tests for _is_credential_param / sanitize_source AND the typed source_keys._remove_credential_query_params / _is_credential_name proving the FINAL credential query-param NAME grammar (Finding 1 + Finding 2). These tests gate the MERGED single production task 073.002-T (former stream-B code task 073.004-T is retired/merged into 073.002-T). Path-embedded secret redaction (former stream C / 073.005-T/073.006-T) is REJECTED/retired per the operator contract; not this task and not in executable scope.

EXPLICIT EXACT-MATCH VOCABULARY (Finding 1): the matcher recognizes an explicit, case-insensitive credential-name vocabulary by EXACT equality — the legacy `startswith`/prefix heuristic is REPLACED, not extended. Redacted (case-insensitive EXACT match): the individually-enumerated existing/legacy/cloud names preserved from current behavior (token, access_token, key, api_key, secret, auth, sig, signature, x-amz-credential, x-amz-signature, x-amz-security-token, x-goog-signature), the names previously caught only by the `startswith("auth")` prefix and now individually enumerated to preserve prior coverage (auth_token, authorization), the intended additional legacy/cloud names (refresh_token, apikey, client_secret, x-goog-credential, awsaccesskeyid), PLUS the newly added password, pwd, passwd, code, plus case-varied forms (Passwd/PASSWD/Refresh_Token/REFRESH_TOKEN/AWSAccessKeyId/X-Goog-Credential/etc.). Plan H1 holds the authoritative list.

HONEST COMPLETENESS (Finding 7): the vocabulary is NOT claimed universally complete. Add benign PREFIX-preservation fixtures asserting that names NOT enumerated in the vocabulary are INTENTIONALLY NOT redacted under exact match — including suffixed/prefixed variants of real credential names that the retired `startswith` heuristic used to catch but exact-match deliberately does not (e.g. `token_v2`, `access_token2`, `my_api_key`, `x-amz-credential-v4`) — proving exact-match semantics and recording unknown/variant names as accepted, intentionally-unredacted residual absent explicit product support.

BENIGN PRESERVATION (Finding 1) — these MUST NOT redact under exact match (they were FALSE POSITIVES under the retired startswith heuristic): tokenizer, keynote, secretary, authorship, signal, password_policy, pwd_length, client_secretary, codec, code_version, passwd_file, refresh_token_ttl, and case-varied variants of every one (Tokenizer, KeyNote, Secretary, Authorship, Signal, Password_Policy, PWD_Length, Client_Secretary, Codec, Code_Version, Passwd_File, PASSWD_HASH, Refresh_Token_TTL, REFRESH_TOKEN_EXPIRY).

BOUNDED DECODE — QUERY NAMES ONLY, BOTH PATHS (Finding 2): assert bounded percent-decoding is applied to the query-parameter NAME on BOTH the string sanitizer path and the typed sanitizer path; the vocabulary is re-checked after EACH decode layer, capped at 5 layers, and fails closed (treated as credential) if the name is still transforming past the cap. Cover: `%70assword`→password (1 layer), `%2570assword`→`%70assword`→password (2 layers), a deeper still-valid layered case that resolves to a vocabulary name within the cap, and an over-cap case (>5 layers still transforming) that fails closed. Assert NO decoding is applied to URL PATHS or to query-parameter VALUES.

Acceptance criteria: (1) new-name + case-varied + bounded-decode (1/2/deeper/over-cap) redaction cases FAIL on HEAD (currently unmatched); (2) ALL benign preservation cases (incl. tokenizer/keynote/secretary/authorship/signal and passwd_file/refresh_token_ttl and case-varied variants) assert NON-redaction; (3) the enumerated existing/legacy/cloud vocabulary (incl. the newly-enumerated auth_token/authorization/refresh_token/apikey/client_secret/x-goog-credential/awsaccesskeyid) still redacts by exact match (coverage parity/expansion for real credential names); (4) benign PREFIX-preservation fixtures (`token_v2`, `access_token2`, `my_api_key`, `x-amz-credential-v4`) assert NON-redaction, proving exact-match semantics and the intentionally-unredacted-variant residual (Finding 7); (5) bounded query-name decode is exercised on BOTH the string and typed sanitizer paths, with over-cap fail-closed; (6) NO path or query-VALUE decoding, and NO path-embedded-secret assertions (path redaction is REJECTED/retired); (7) no production code changed. Execution posture: test-first.
