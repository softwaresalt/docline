Make 064.016-T green. Code domain only, <=2 files (fetch/http.py, fetch/crawl.py). Two coupled changes: (1) add FetchResponse.body_byte_count:int (with a DEFAULT so the frozen dataclass stays valid - FetchResponse's last field redirect_count:int=0 already carries a default, so body_byte_count MUST be declared body_byte_count:int=0 or inserted before redirect_count; a non-default field appended after a defaulted one raises TypeError at import and would break the whole fetch/parity suite) set from the length of the bytes read by the bounded reader BEFORE decoding (the body_bytes already materialized by the streamed read in 064.013-T) - the accurate raw wire count for per-response accounting/observability; (2) enforce the aggregate MAX_TOTAL_FETCH_BYTES budget with a REQUEST-SCOPED remaining-byte budget THREADED into fetch_page and its bounded reader, decremented WHILE CHUNKS ARE READ, so the budget is enforced during transfer rather than summed after a successful FetchResponse returns. A post-return crawl accumulator is insufficient: the response that crosses the budget has already been fully read, and bytes from failed per-response reads retried by _fetch_with_retries never return a FetchResponse to accrue. fetch/crawl.py seeds ONE request-scoped budget per crawl request and passes it through every fetch_page call - main pages, retries, and ancillary robots.txt (_robots_allow) / TOC (_discover_toc_links) fetches - so all transfer for the request decrements the same budget. Isolated from 064.013-T so the shared-model (FetchResponse) blast radius and byte-accurate during-read accounting land in one bounded task. Cross-interface (CLI crawl too). See plan H7 item 3 / cycle-3 + cycle-4 remediation.

<!-- BEGIN:acceptance-criteria -->
- FetchResponse gains body_byte_count:int WITH A DEFAULT (body_byte_count:int=0, or placed before the defaulted redirect_count field), set from len(body_bytes) captured BEFORE body_bytes.decode(...) in fetch/http.py fetch_page (the raw wire byte count, not len(body) or len(body.encode())). Existing FetchResponse constructors that omit it must remain callable.
- The aggregate budget is enforced by a request-scoped remaining-byte budget threaded into fetch_page and its bounded reader: the reader decrements the remaining allowance as each chunk is read and aborts the read MID-STREAM by raising AggregateBudgetExceededError the moment the remaining aggregate allowance would be exceeded (the crossing response is never fully buffered). AggregateBudgetExceededError is a DoclineError subclass (typed-error convention; maps to the MCP boundary's DoclineError handling). The budget defaults to unbounded/None for a standalone single fetch so existing CLI single-fetch callers are unaffected.
- Every consumer decrements the SAME request-scoped budget while reading: main-page reads, over-cap attempts that raise and are retried by _fetch_with_retries (retried bytes are counted, not free), and ancillary robots.txt / mdBook TOC fetches.
- Abort propagation (blocking): because AggregateBudgetExceededError subclasses DoclineError, it would be SWALLOWED by crawl.py's broad `except (DoclineError, OSError)` handlers. It MUST be re-raised at ALL FOUR broad-handler sites - crawl() main loop (~line 178), _fetch_with_retries (~line 382), _robots_allow (~line 406), and _discover_toc_links (~line 465) - by adding `except AggregateBudgetExceededError: raise` immediately before each broad handler, mirroring the existing `except CrawlUrlRejectedError: raise` pattern (_robots_allow has no such prior re-raise clause and needs one added). The budget error MUST propagate cleanly out of crawl() as a RAISE (not be recorded as a per-page skipped CrawlResult, which would let the crawl continue over the remaining frontier with budget=0 and degrade a byte-abort into a max_pages x backoff time-exhaustion).
- 064.016-T harness passes green (non-ASCII multibyte, invalid-byte, and the parametrized during-read enforcement across main-page mid-read abort, retried-failure accrual, and ancillary-fetch accrual; crawl() RAISES rather than returning skipped results).
