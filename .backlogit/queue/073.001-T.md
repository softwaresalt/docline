This is HELPER/in-memory coverage ONLY: assert the in-memory metadata.source and a reconstructed model_dump JSON (the in-process shape cli.py:381 later serializes — NOT the live CLI stdout) contain no userinfo and no recognized credential query params for all four URL-bearing source kinds. The LIVE cli.py:381 stdout sink is asserted SOLELY by 073.007-T (stream-A userinfo subset) and 073.009-T (A2+B2 composition), not here (PM/on-disk metadata.json is NOT a default-path sink and is not asserted here).

TYPED-FIELD PRESERVATION (2026-09-15 operator contract, Finding 3): additionally assert the typed sanitization path (src/docline/elt/source_keys.py — sanitize_source_key / _sanitize_url_field / _remove_credential_query_params) sanitizes ONLY URL fields (userinfo + recognized credential query-param names) and explicitly-secret typed config fields, while BYTE-PRESERVING the non-credential provenance typed fields — source branch, path_glob / include patterns, manifest ID, and local filesystem paths — which appear UNCHANGED in the resulting metadata/source key.

EXPLICIT LOCAL-SOURCE PRESERVATION FIXTURES (2026-09-15 operator contract, Finding 6): in addition to the four URL-bearing kinds, add explicit executable fixtures for LocalFileSource and ManifestLocalSource. These kinds carry NO URL credential; assert their local filesystem `path`, `include` patterns, source `branch`/`path_glob`, and manifest `id` are emitted BYTE-FOR-BYTE UNCHANGED through build_source_key/sanitize_source_key — INCLUDING when a benign path or include pattern contains credential-looking text (e.g. an include glob `**/*?token=*` or a path segment `/tokenizer/`), which MUST NOT be interpreted as a credential structure. Identify the exact source_keys behavior under test: sanitize_source_key(LocalFileSource) and sanitize_source_key(ManifestLocalSource) return the same value as build_source_key for the provenance fields (no redaction), because the operator contract designates these as provenance, not access credentials.
