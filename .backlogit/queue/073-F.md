## Operator-Decision Revision — 2026-09-15 (scope correction, supersedes cycles 1–3 path work)

**FINAL Operator Contract (2026-09-15, authoritative — supersedes all earlier
remediation language).** In addition to the product boundary below, the FINAL
contract fixes the executable grammar and handoff: (1) replace every legacy query-name
`startswith` heuristic with an explicit, case-insensitive, EXACT-match credential-name
vocabulary (legacy/cloud variants individually enumerated; benign names such as
tokenizer/keynote/secretary/authorship/signal/password_policy/pwd_length/
client_secretary/codec/code_version/passwd_file/refresh_token_ttl and case variants
preserved); (2) bounded decode of QUERY-PARAMETER NAMES ONLY on BOTH the string and
typed sanitizer paths (re-check vocabulary after each layer, max 5 layers, fail closed
past the cap; no path or value decode); (3) sanitize URL fields + explicitly-secret
typed fields while byte-preserving branch/path_glob/manifest ID/local path/include; (4)
keyword-only `sanitized_source` that RAISES a typed, non-leaking exception on
compound-key omission (whole-key sentinel removed); (5) a satisfiable final live
default-stdout composition gate (073.009-T) proving the A2+B2 composition for userinfo
and ALL recognized new names — added as an additional test task blocking both code
tasks so the test-first DAG stays satisfiable; (6) LocalFileSource/ManifestLocalSource
paths, includes, AND manifest IDs are preserved. Handoff: Stage owns and COMMITS its own
planning/backlog artifacts on chore/stage-064-s; the Orchestrator only coordinates
review, the remote staging gate, and the Ship handoff. See the plan and deliberation
FINAL Operator Contract sections for the authoritative rationale.

The operator issued an authoritative scope correction for 064-S/073-F that
SUPERSEDES the path-redaction requirements introduced during prior review
remediation (cycles 1–3):

* Docline MUST NOT scan, interpret, or rewrite source-document content for secrets.
* Ordinary URL paths are source identifiers/content locations and MUST remain
  BYTE-FOR-BYTE unchanged (e.g. `/authentication/overview`, `/tokenizer/config`,
  `/keys/rotation`, `/docs/100%25-off`). Path-secret detection/redaction is an
  UPSTREAM DLP concern, not Docline's responsibility.
* Docline's responsibility is limited to NOT RE-EMITTING **structured access
  credentials** supplied to connect to a source: URL user-info, explicitly
  recognized credential query parameters, and typed config fields designated
  secret — in generated metadata, stdout/logs, warnings, or errors.
* Useful source provenance and benign URL/query/path data are preserved.

Effect on this feature: Streams A and B remain executable (they act only on
structured access credentials). Stream C (path-embedded secret redaction,
073.005-T + 073.006-T) is REJECTED and retired non-destructively. Task 073.007-T
is narrowed to structured-access-credential coverage plus benign-path preservation.
This revision also resolved the three P1 blockers from the cycle-3 re-review — the
unsatisfiable 073.002-T↔073.007-T path milestone, benign-path over-redaction, and
literal-percent (`%25`) rejection — by REMOVING the unjustified path requirement,
not by adding more path parsing. See the plan and deliberation Operator-Decision
Revision sections for the full rationale and the REJECTED-alternatives record.
