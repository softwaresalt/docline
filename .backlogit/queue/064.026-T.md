Implement the request-amplification bound on the SHARED fetch code to turn 064.025-T green. Code domain only. Two minimal edits: (1) src/docline/fetch/crawl.py gains a per-request fetch-attempt (frontier-pop) counter incremented on EVERY frontier pop so the print-page, duplicate-final-URL, and out-of-scope-section branches (which today `continue` WITHOUT `page_count += 1`) all count toward the bound, aborting the crawl with a typed error once attempts would exceed MAX_FETCH_ATTEMPTS; (2) src/docline/app_models.py FetchRequest.depth gains a hard upper bound Field(default=0, ge=0, le=64) (default preserved so depth stays optional). Hardens BOTH interfaces (CLI docline fetch and the MCP fetch tool) - a cross-interface behavior change (see plan Rollback/Risks). This task does NOT own the per-response or aggregate BYTE budgets (064.013-T / 064.017-T / 064.024-T) - those bound transfer VOLUME; this bounds request COUNT. Split out of 064.013-T (which is pinned to app_models.py max_pages + fetch/http.py streamed byte cap = 2 files) because the fetch-attempt counter lives in fetch/crawl.py - a third file plus new loop-guard/abort logic that would breach 064.013-T's <=2-file / function envelope. See docs/plans/2026-08-27-mcp-stdio-server-plan.md (Plan Hardening H7 item 4).

<!-- BEGIN:acceptance-criteria -->
- fetch/crawl.py enforces a per-request fetch-attempt bound via a named module constant MAX_FETCH_ATTEMPTS = 4 * MAX_PAGES_LIMIT = 4000. A fetch_attempts counter increments on EVERY frontier pop (an actual main-page fetch), so the print-page (`_is_print_page`) branch, the duplicate (`final_key in emitted_urls`) branch, and the out-of-scope (`domain_lock and not _url_within_section_scope(final_url, ...)`) branch - all of which currently `continue` without incrementing page_count - count toward the bound. Implement as a pre-fetch increment plus abort, or extend the loop guard to `while frontier and page_count < crawl_config.max_pages and fetch_attempts < MAX_FETCH_ATTEMPTS`. Crossing MAX_FETCH_ATTEMPTS aborts the crawl by RAISING a typed error (a DoclineError subclass; no bare except) - it does NOT silently return the accumulated skipped results. Boundary: exactly 4000 fetch attempts are allowed; the 4001st is refused.
- app_models.py: FetchRequest.depth gains a hard upper bound MAX_DEPTH_LIMIT = 64 (Field(default=0, ge=0, le=64) - the existing default=0 is PRESERVED so depth stays optional and is NOT made required); depth 0..64 inclusive accepted, >= 65 raises ValidationError (surfaces as -32602 on the MCP boundary), and a request omitting depth still validates (defaults to 0). depth flows into CrawlConfig.max_depth (app.py:606), so the model bound closes the untrusted-input depth vector at the boundary.
- 064.025-T harness passes green (fetch-attempt amplification cap + depth upper bound).
- The existing tests/fetch suite remains green under the new bounds (or is deliberately updated for the new limits, documented in the commit). Typed errors only; no bare except.
- ruff check ., ruff format --check ., pyright src/ clean.
