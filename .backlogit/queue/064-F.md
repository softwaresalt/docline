Make docline usable over a local stdio MCP connection by adding a runnable JSON-RPC 2.0 stdio server that wraps the existing DoclineMcpServer adapter, and ship a docline-mcp console executable (docline-mcp.exe on Windows). Source stash: 14E46B47. The adapter, shared manifest, and transport guard already exist; this feature adds the missing runnable protocol surface + entry point, hardened for the untrusted stdio boundary. Executable — no external credentials, paid calls, or corpora required. Ranked high product-outcome (interoperability/composability outranks feature novelty).

- docline-mcp (and python -m docline.mcp) run a stdio JSON-RPC 2.0 loop wrapping DoclineMcpServer. The stdio loop reads frames NON-GREEDILY (read1/os.read, never blocking to fill a whole CHUNK_SIZE) and FLUSHES stdout after every response, and an INTERACTIVE automated subprocess smoke test (subprocess.Popen: send+flush one frame, require its response BEFORE sending the next with stdin still open, then EOF; timeout-bounded reads) proves no live stdio deadlock and asserts advertised-tool-name parity (064.008-T green@064.003-T).
- tools/list (via new list_callable_tools()) advertised set == callable allow-list; every advertised tool is dispatchable; legacy list_tools() unchanged (full manifest, existing parity test green).
- tools/call fetch/process parity with CLI execute_fetch/execute_process; every successful tools/call (fetch, process, export_schema) returns a standards-valid MCP CallToolResult - result.content is a non-empty ContentBlock[] (typed blocks) and result.structuredContent mirrors the domain result when applicable - NOT a raw FetchResult/ProcessResult/str serialization (which real MCP clients reject); for fetch/process a validated-but-failed result (success=False) maps to isError=true with sanitized error text carried in content (export_schema's only failure mode, non-empty arguments, is a -32602 invalid-params envelope, not an isError result). Both eras emit the identical CallToolResult body (the modern era wraps it in resultType:'complete'). Asserted by the legacy harness 064.005-T (green@064.002) and the modern harness 064.021-T scenario c (green@064.022); produced by dispatch()'s inline tools/call shaping (064.002 body / 064.022 modern wrapper).
- JSON-RPC conformance: -32600 Invalid Request for non-object root / bad-or-missing jsonrpc / missing-or-non-string method / present non-string-non-number id (object/array/bool/null - MCP 2026-07-28 RequestId permits only string|number; the malformed id is never echoed, the -32600 frame carries id:null; an absent id stays an id-less notification, a present null id is -32600). Because request-shape validation runs before era routing in the single hardened dispatch, both eras reject a malformed id identically.
- Security hardening H1-H7 all covered by passing tests: H1 workspace_root REJECT (-32602) + schema omission + server-root pin; H2 bounded stdin read/drain; H3 error non-disclosure (envelope + isError); H4 closed allow-list fail-closed; H5 stdout hygiene; H6 SSRF-by-DNS-resolution (resolve + address-pinned connect on initial URL and every redirect, reject hostname->loopback/private); H7 fetch resource caps (hard max_pages upper bound MAX_PAGES_LIMIT = 1000 (Field ge=1, le=1000), over-limit -> -32602; streamed MAX_RESPONSE_BYTES = 10 MiB (10485760 bytes) incl. redirects; and a byte-ACCURATE aggregate MAX_TOTAL_FETCH_BYTES = 512 MiB (536870912 bytes) crawl budget enforced by a request-scoped remaining-byte budget threaded into fetch_page/the bounded reader and decremented per chunk WHILE bytes are read (counting retried/failed over-cap attempts and ancillary robots/TOC fetches, aborting mid-read before the crossing response is fully buffered) - NOT a post-return accumulator; FetchResponse.body_byte_count is retained only as per-response observability, never summed for enforcement - proven with non-ASCII and invalid-byte payloads so decode/re-encode undercount cannot bypass the cap; PLUS a request-amplification bound (§H7 item 4, request COUNT not byte VOLUME): a hard fetch-attempt/frontier-pop cap MAX_FETCH_ATTEMPTS = 4000 in fetch/crawl.py counting EVERY frontier pop - so the print-page / duplicate-final-URL / out-of-scope-section branches that today fetch WITHOUT incrementing page_count (only the print branch also enqueues links) are bounded - aborting the crawl with a typed error, and a hard FetchRequest.depth upper bound MAX_DEPTH_LIMIT = 64 (Field default=0, ge=0, le=64; default preserved so depth stays optional), over-limit -> -32602).
