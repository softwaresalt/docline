Make docline usable over a local stdio MCP connection by adding a runnable JSON-RPC 2.0 stdio server that wraps the existing DoclineMcpServer adapter, and ship a docline-mcp console executable (docline-mcp.exe on Windows). Source stash: 14E46B47. The adapter, shared manifest, and transport guard already exist; this feature adds the missing runnable protocol surface + entry point, hardened for the untrusted stdio boundary. Executable — no external credentials, paid calls, or corpora required. Ranked high product-outcome (interoperability/composability outranks feature novelty).

<!-- BEGIN:dod -->
- docline-mcp (and python -m docline.mcp) run a stdio JSON-RPC 2.0 loop wrapping DoclineMcpServer.
- tools/list (via new list_callable_tools()) advertised set == callable allow-list; every advertised tool is dispatchable; legacy list_tools() unchanged (full manifest, existing parity test green).
- tools/call fetch/process parity with CLI execute_fetch/execute_process; success=False maps to isError.
- JSON-RPC conformance: -32600 Invalid Request for non-object root / bad-or-missing jsonrpc / missing-or-non-string method.
- Security hardening H1-H7 all covered by passing tests: H1 workspace_root REJECT (-32602) + schema omission + server-root pin; H2 bounded stdin read/drain; H3 error non-disclosure (envelope + isError); H4 closed allow-list fail-closed; H5 stdout hygiene; H6 SSRF-by-DNS-resolution (resolve + address-pinned connect on initial URL and every redirect, reject hostname->loopback/private); H7 fetch resource caps (hard max_pages upper bound -> -32602, streamed MAX_RESPONSE_BYTES incl. redirects, aggregate MAX_TOTAL_FETCH_BYTES crawl budget).
- Cross-interface: shared-fetch hardening (url_policy/http/crawl/app_models) applies to CLI fetch too.
- Quality gates green: ruff check, ruff format --check, pyright src/, pytest.
Source plan: docs/plans/2026-08-27-mcp-stdio-server-plan.md (Security PASS after adversarial multi-persona review; cycle-2/2b remediation).
