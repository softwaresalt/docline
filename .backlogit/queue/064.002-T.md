<!-- BEGIN:acceptance-criteria -->
- src/docline/mcp/stdio.py provides pure dispatch(message, server) and serve(stdin, stdout, server=SERVER), reserving real stdout for JSON-RPC frames; clean EOF exit. serve() reads frames with a NON-GREEDY input primitive (read1 / os.read) that returns as soon as ANY bytes are available and never blocks waiting to fill a whole CHUNK_SIZE, and EXPLICITLY FLUSHES stdout after writing EVERY response frame - so an interactive client that sends one frame, waits for its response, then sends the next (with stdin still open; the 064.008-T live smoke test) never deadlocks. A greedy read(CHUNK_SIZE) that waits for the full chunk after a short frame, or a block-buffered stdout that withholds the response until the pipe closes, would live-lock that probe (cycle-8).
- dispatch() performs JSON-RPC request-shape validation returning -32600 Invalid Request for a non-object root, a missing/invalid jsonrpc member, or a missing/non-string method - distinct from -32700 (bad JSON) and -32601 (unknown method).
- Legacy-era method map: initialize (capabilities + protocolVersion 2025-11-25 + serverInfo, all sourced from the adapter describe_server() accessor introduced by 064.015 - NOT hardcoded in stdio.py, so the transport stays a pure translator and the identity single-source invariant holds from first commit); notifications/initialized silent; ping -> {}; tools/list via server.list_callable_tools(); tools/call via server.call_tool; id-less notification silent; and dispatch()'s tools/call handler shapes every tools/call return (fetch/process/export_schema) INLINE into a standards-valid MCP CallToolResult - result.content is a non-empty ContentBlock[] (typed text block(s)), result.structuredContent mirrors the domain result when applicable, and success=False -> isError=true with sanitized error text carried in content - NOT the raw FetchResult/ProcessResult/str serialized directly. The modern branch (064.022) REUSES this same dispatch output and applies only the resultType wrapper on top, so both eras emit the identical CallToolResult body (no per-era drift, no extra transport function).
- Bounded binary frame read/drain helper AND its runtime enforcement (H2): fixed-chunk reads (each via the NON-GREEDY read1/os.read primitive, returning available bytes without blocking to fill the chunk) up to MAX_FRAME_BYTES scanning for the newline, bounded drain of an oversized/unterminated frame - NOT a post-read length check on an unbounded readline(). A carry-over buffer preserves any bytes read AFTER a frame's newline terminator (a fixed-size read can return a newline plus the head of the next frame) and seeds the next frame from them, in BOTH the normal-frame path AND the oversized-drain path, so a following JSON-RPC request in the same chunk is never dropped. RecursionError/ValueError degrade to an envelope.
- Greens: 064.001-T legacy transport assertions (handshake + tools/list), 064.005-T (dispatch parity + CallToolResult wire shape/error/-32600/notification), the H2 scenario in 064.006-T, the H6-literal scenario in 064.007-T, and ALL of 064.014-T (the shared-fetch SSRF/cap guards from 064.011/064.013/064.017 enforce automatically once server.fetch is routed - no boundary wiring needed here).
- Existing tests/parity/test_mcp_adapters.py and test_manifest_parity.py unchanged and passing. Remaining stdio guardrails H1/H3/H4/H5 (064.006-T H1/H3, 064.007-T H4/H5) remain red until 064.009-T; modern-era negotiation remains red until 064.020-064.023.
