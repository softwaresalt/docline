<!-- BEGIN:acceptance-criteria -->
- src/docline/mcp/stdio.py provides pure dispatch(message, server) and serve(stdin, stdout, server=SERVER), reserving real stdout for JSON-RPC frames; clean EOF exit.
- dispatch() performs JSON-RPC request-shape validation returning -32600 Invalid Request for a non-object root, a missing/invalid jsonrpc member, or a missing/non-string method - distinct from -32700 (bad JSON) and -32601 (unknown method).
- Legacy-era method map: initialize (capabilities + protocolVersion 2025-11-25 + serverInfo, all sourced from the adapter describe_server() accessor introduced by 064.015 - NOT hardcoded in stdio.py, so the transport stays a pure translator and the identity single-source invariant holds from first commit); notifications/initialized silent; ping -> {}; tools/list via server.list_callable_tools(); tools/call via server.call_tool; id-less notification silent; success=False -> isError result mapping.
- Bounded binary frame read/drain helper AND its runtime enforcement (H2): fixed-chunk reads up to MAX_FRAME_BYTES scanning for the newline, bounded drain of an oversized/unterminated frame - NOT a post-read length check on an unbounded readline(). A carry-over buffer preserves any bytes read AFTER a frame's newline terminator (a fixed-size read can return a newline plus the head of the next frame) and seeds the next frame from them, in BOTH the normal-frame path AND the oversized-drain path, so a following JSON-RPC request in the same chunk is never dropped. RecursionError/ValueError degrade to an envelope.
- Greens: 064.001-T legacy transport assertions (handshake + tools/list), 064.005-T (dispatch/error/-32600/notification), the H2 scenario in 064.006-T, the H6-literal scenario in 064.007-T, and ALL of 064.014-T (the shared-fetch SSRF/cap guards from 064.011/064.013/064.017 enforce automatically once server.fetch is routed - no boundary wiring needed here).
