Author the RED unit harness (tests/fetch/) proving the aggregate MAX_TOTAL_FETCH_BYTES budget counts RAW WIRE BYTES (not decoded characters or a re-encode) AND is enforced by a request-scoped remaining-byte budget decremented WHILE CHUNKS ARE READ (not summed only after fetch_page returns a successful FetchResponse). Tests domain only. This isolates the byte-accuracy + during-read enforcement concern (and the FetchResponse shared-model blast radius) from the per-dimension caps (064.012/064.013). Verifies red until 064.017-T (scenarios a, b, c(i), c(ii)) and 064.024-T (scenario c(iii), the ancillary-fetch sub-vector, split out cycle-6). See plan Plan Hardening H7 item 3 and cycle-3 + cycle-6 remediation.

<!-- BEGIN:acceptance-criteria -->
- Scenario (a): a non-ASCII multibyte body (raw byte length > character length) accrues its RAW byte length toward MAX_TOTAL_FETCH_BYTES, not len(body) characters.
- Scenario (b): an invalid-byte body (where UTF-8 decode with errors=replace collapses bytes to U+FFFD) accrues its ORIGINAL raw byte length, not the replaced-character length.
- Scenario (c) [parametrized during-read enforcement across all consumers]: a request whose cumulative RAW bytes exceed MAX_TOTAL_FETCH_BYTES is aborted even though the decoded character total stays under budget (undercount-bypass), covering: (i) a main-page response that crosses the remaining budget aborts MID-READ (the crossing response is not fully buffered before the abort); (ii) a repeated-failure case - an over-cap attempt that raises and is retried by _fetch_with_retries still decrements the shared request budget for the bytes it read (retried attempts are not free); (iii) an ancillary fetch (robots.txt via _robots_allow and/or a mdBook TOC script via _discover_toc_links) decrements the SAME shared request budget, so oversized-but-under-cap ancillary payloads cannot amplify transfer outside it. In every sub-case crawl() itself RAISES the budget error (AggregateBudgetExceededError propagates out of crawl) - it is NOT recorded as a per-page skipped CrawlResult and the crawl does NOT continue over the remaining frontier with budget=0.
- Pinned limit (plan §H7 Selected numeric limits): MAX_TOTAL_FETCH_BYTES = 512 MiB (536870912 bytes). Tests assert the request-scoped budget starts at 536870912 and aborts a read mid-stream the instant cumulative request raw bytes would exceed 536870912 (a total of exactly 536870912 raw bytes across the request is allowed; the crossing byte triggers the abort). Exact-boundary over-read guard: via a fake/instrumented transport recording every read size, the harness asserts the reader consumes AT MOST the remaining allowance + 1 (only the single crossing byte) on the response that trips the budget - NOT a whole extra CHUNK_SIZE chunk - and that each read request is bounded by min(CHUNK_SIZE, per_response_remainder + 1, aggregate_remainder + 1). The main-page (c)(i) and retried-failure (c)(ii) sub-cases assert the crossing-byte-only transfer; the ancillary (c)(iii) sub-case asserts the same bound and is greened by 064.024-T.

- No production code changed in this task (tests only).
- Scenario budget: 3 (raw-multibyte, raw-invalid-byte, parametrized during-read enforcement) - within the <4 heuristic.
